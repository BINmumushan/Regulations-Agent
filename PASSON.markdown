21. **提高上下文识别**（已实现）：第二个问题里的“它/它们/其/这个/该政策/上述内容”等指代词，会先替换成上一轮问题中的具体话题（如“数字孪生”），再检索和作答；示例“数字孪生是什么？”→“园区对它有什么期望吗？”应理解为“园区对数字孪生有什么期望吗？”。
22. **来源默认收起，想看再展开**（已实现）：回答下方的来源改为“来源 (N)”+ 下拉箭头，点击展开来源文件标签，再点收起。
23. **未知回答不提供下载按钮，导出 PDF 也不含该段问答**（已实现）：委婉未答的消息 `unknown=true`，网页不渲染下载图标；前端和后端都会把“未知问题 + 未知回答”这一组从导出记录中过滤。

25. **回答不要提及“知识库”等后台字眼**（已实现）：提示词要求面向用户措辞，可用“根据我的理解”“从已有资料看”“据了解”等委婉表达；`_sanitize_answer` 再做输出清洗兜底，并保护《书名号》里的正式文件名。

### 已完成的能力（详见第 5 节）

- 多格式读取：`.doc`（OLE/COM/伪 DOCX/RTF/HTML 识别）、WPS、PPTX、图片 OCR、损坏 docx XML 兜底；结构感知切块；本地向量化 + FAISS。
- 检索：BM25+jieba 与 FAISS 混合、多问句轮转合并、章节加权、层级过滤、书名号点名文件、同文件上下文补全、总结/梳理类按来源补齐并按文件分开作答、`REGION_KEYWORDS` 地区跨层级兜底、默认苏州/江苏语境过滤。
- 作答：严格 grounding 提示词（防幻觉、精准不冗长、按需列举、多文档总结逐点标注《文件名》来源、不知道时委婉未答且无来源、不要求用户上传文档、大段内容简练概括且不越库）、来源只列文档名不显示页码。
- 报告模式：识别“解读/报告/汇报/提纲/要点/主要内容”等词，用结构化解读/报告模板作答（8 个小节模板、没有依据的小节省略、逐点标注《文件名》来源、未知仍委婉未答且无来源）。
- 对话型问答：`answer_question(history=...)` 多轮承接（最多 8 轮）、承接问题改写后检索、无新命中时基于历史回答兜底并沿用来源。
- 入口：命令行/交互/FastAPI 聊天型网页（气泡对话、多轮承接、无上传入口、Markdown 排版、侧边栏多会话、来源下拉、首轮不显示下载、后续图标导出整段对话 PDF、未知回答不下载且导出时过滤）。
- 指代识别：`_resolve_referents` + `_extract_topic` 规则化替换指代词；支持同句多问题（先按句切分、取最近话题）与历史多轮（跳过含指代的历史轮次继续向前找），配合强化后的 `REWRITE_PROMPT`/`SYSTEM_PROMPT`，承接问题先变成独立查询再检索。
- 回答措辞：`SYSTEM_PROMPT`/`REPORT_SYSTEM_PROMPT` 禁止回答中出现“知识库/库内/知识库内容”等后台术语；`_sanitize_answer` 将残留的“知识库”替换成“已有资料/根据我的理解”等表达，且保护《书名号》文件名。
- PDF 导出：reportlab 中文 A4 美化排版，不显示来源；整段对话导出时过滤委婉未答问答组。
- 联网搜索：未知回答自动附“需要我帮你联网搜索相关的答案吗？”；用户同意后由 [kb_agent/web_search.py](kb_agent/web_search.py) 走 Bing RSS/HTML + 搜狗/百度兜底，DeepSeek 只依据搜索结果整理，答案固定带“非官方、仅供参考、请谨慎辨别”声明，`web=true`、sources 为空。

## 1. 项目定位

基于 LangChain 的严格知识库问答 Agent：

- 用户把 PDF（含扫描件自动 OCR）、TXT/MD、CSV、DOCX、Excel 放入 `data/pdfs/` 作为知识库。
- 回答问题时**只能依据知识库内容作答**；知识库没有明确内容时委婉回复“我还不懂这些，你可以换个问法再问一次。”，不显示来源，也不要求用户上传或补充文档。
- 聊天模型用 DeepSeek，向量化用本地模型（DeepSeek 不提供 embedding 接口）。
- 提供命令行、交互模式、FastAPI 网页版三种使用方式。
- 对话型：支持多轮对话，第二个问题可承接第一个问题的回答；网页为聊天型界面。
- 知识库按政策层级分区：`01国家政策`、`02省级政策`、`03市级政策`、`04园区政策`、`05其他地区政策`。
- 用户后续会传入 100+ 份文档，学习/检索逻辑必须通用，不能只针对某几份文档打补丁。
- 默认以苏州/江苏为主要语境：未点名外地、未要求横向比较时，不引入其他地区政策。
- 知识库没有明确答案时，先委婉未答并征询是否联网搜索；用户同意后才搜索公开网页，且答案带“非官方、仅供参考、请谨慎辨别”声明。

## 2. 用户核心要求

1. 严格知识库问答：只能依据知识库中明确写出的内容作答；不知道时用委婉表达“我还不懂这些，你可以换个问法再问一次。”，且不显示来源、不要求用户上传或补充文档。
2. 分批传入 100+ 份文档，阅读逻辑/学习逻辑/检索逻辑必须通用。
3. 使用 PyCharm + LangChain 进行调试。
4. 需要网页版问答（浏览器直接提问）。
5. **不要占用 8000 端口**，由用户在 PyCharm 里自己启动服务。
6. **知识库分层检索**：`data/pdfs/` 下分 `01国家政策`、`02省级政策`、`03市级政策`、`04园区政策`、`05其他地区政策`；提问时若用户明确指定层级（如“国家政策”“省级”“市级”“园区”“其他地区”），只查该层级；**没有明确指令时，从全部政策中检索**。
7. **网页不需要上传知识库**：用户只会本地放文件入库；网页上已移除上传入口。网页问答成组展示：答案紧跟问题下方，最新问答组在最上方。
8. **完成所有任务前不准停止！！！！！**：用户原话、最高优先级；用户已多次强调并反复催促，这是最重要的工作习惯要求。承诺“继续”就必须在同一轮内持续调用工具，直到全部完成再结束。
9. 用户当前正在补齐市级政策，要求“学习后确保能够回答用户的问题”。
10. **网页问答成组展示**：每个问题的答案紧跟问题下方，新的问答组显示在旧问答上方。
11. **总结/梳理/列举类问题精准且不冗长**：命中文件的相关片段全部进入上下文；总结/梳理/介绍类先概括核心要点、控制篇幅，不要逐文件铺开全部细项，也不要过于简洁；确需区分文件时再按《文件名》分组，不能把多份文件的小点混在一起；多文档总结时每个要点后标注（《文件名》）来源。
12. **所有文件都要自检自查、自纠**：新增文档后要做全量完整性自检，不能只修反馈到的文件。
13. **代码不允许写死知识库文件名**：新增文件或改文件名不应改业务代码；测试夹具文件名集中管理。
14. **未答表达要委婉**：不直接说“我不知道”，改用“我还不懂这些，你可以换个问法再问一次。”；不得要求用户上传或补充文档（用户无法编辑知识库）。
15. **大段内容作答要精准但不特别冗长**：既不要逐文件铺开，也不要过于简洁；只能依据知识库内文档内容概括，不得说知识库之外的内容。
16. **来源只列文档名**：回答的来源只体现命中的几个文档，不显示页码。
17. **不知道的问题不显示来源**：即使检索到了文档，只要最终回答为委婉未答，来源列表也保持为空。
18. **不得要求用户上传文档**：回答中不能出现“补充文档/上传文档”等要求，因为用户无法编辑知识库。
19. **PASSON/README 只在用户要求时更新**：每次操作完成后不主动修改这两个文档。
20. **多轮对话**：用户问第二个问题时，可以基于第一个问题的回复回答，并可加上正常交流的感觉。
21. **网页改为聊天型 Agent**：改成大致的聊天界面（气泡对话）。
22. **PDF 下载规则**：第一个问题不显示下载 PDF 按钮；后续需要下载时显示得隐蔽一些，用图标代替文字；下载后续回答时，把前面所有聊天记录全部导出到同一份 PDF。
23. **下载的 PDF 不要显示来源**：PDF 导出只保留问题与回答，不输出来源列表（已实现）。

- DeepSeek 没有 embedding 接口，向量化用本地 `fastembed` + `BAAI/bge-small-zh-v1.5`（512 维，模型已缓存）。
- 本地向量相似度分数普遍只有 0.13~0.16，所以 `SCORE_THRESHOLD` 必须很低（当前 0.05）。
- `config.py` 启动时设置 `HF_ENDPOINT=https://hf-mirror.com` 和 `HF_HUB_DISABLE_XET=1`。
- 扫描 PDF OCR：`PDF_OCR_ENABLED` 默认开启，`PDF_OCR_DPI` 默认 200，模型由 `rapidocr-onnxruntime` 包内置。
- 国家/省级扫描 PDF 均用 `PDF_OCR_DPI=100` 入库，457 页扫描件与省级 88 页扫描件的 OCR 缓存按该 DPI 保存；`.env` 默认仍是 200，重跑入库/重建前先设 `PDF_OCR_DPI=100` 复用缓存。

## 5. 已实现的功能

### 5.1 文档读取（学习逻辑）

- 支持 `.pdf`（pymupdf 提取文字；扫描页自动 RapidOCR 识别）、`.jpg`/`.jpeg`/`.png`（图片 OCR，长图自动分条带）、`.txt`、`.md`、`.csv`、`.docx`（正文+表格；python-docx 解析失败的 WPS 伪关系文档自动回退 XML 提取）、`.doc`（OLE/RTF/HTML/伪 DOCX 自动识别）、`.pptx`/`.ppt`（文本框+表格+备注；旧 `.ppt` 走 PowerPoint/WPS COM，兜底文本扫描）、`.wps`（WPS COM → Word COM → 内置 OLE 解析）、`.xlsx`/`.xlsm`/`.xls`（每个工作表一个片段，工作表名写入章节元数据）。
- **OCR 缓存与并行**：扫描 PDF 识别结果按页写入 `data/ocr_cache/`，图片识别结果同样缓存，中断后重跑可续；页数 ≥10 的扫描 PDF 自动用多进程并行预识别（默认 4 进程）。缓存 key 含 `PDF_OCR_DPI`，不同 DPI 的识别结果分开保存；图片用固定 `dpi=0` 与 PDF 缓存隔离。
- 文本类文件按 `utf-8-sig` -> `gb18030` -> `utf-16` 顺序自动识别编码。
- `.doc` 读取：先按文件头判断真实格式（`D0 CF 11 E0` OLE / `PK` ZIP / `{\rtf` RTF / HTML / 纯文本）；OLE 优先 `Word.Application` → `KWPS.Application` 用 `DispatchEx` 新建独立实例另存为 docx 再解析，COM 失败时用 `olefile` 解析 CLX 段表提取正文。
- **来源标签入库**：切块时每个片段正文前注入 `【来源：文件名】`，让 BM25/向量都能命中文件名；用户点名文件（如“检查一下《大数据局反馈》”）时，检索器会限定到匹配的文件。
- **目录层级识别**：`load_file()` 根据文件父目录名（如 `01国家政策`）提取 `tier` 元数据（去掉前缀数字，得到 `国家政策`）；文件放根目录则没有 `tier`。
- **通用逻辑（不依赖具体文件名）**：支持的扩展名统一由 `loaders.SUPPORTED_SUFFIXES` 定义（入库、上传校验、`self_check_learning.py` 共用）；文件名只作为 `source` 元数据，业务逻辑不写死文件名；点名文件由 `qa.detect_target_sources()` 从《书名号》自动匹配；测试夹具文件名集中在 `tests/test_pipeline.py` 顶部常量，新增或改名文件时只改常量。

### 5.2 切块（学习逻辑）

- 结构感知切块：识别中文政策法规常见标题（`第一章`、`三、`、`（四）`、`第一条`、`（1）` 等）。
- 维护 `section_path` 层级，写入 chunk metadata。
- 切块时会保留原始 Document 的附加元数据（`tier`、`ocr` 等）。
- 按文件边界正确断块，避免不同文件混进同一片段。
- 切块参数：`CHUNK_SIZE=1000`、`CHUNK_OVERLAP=200`。

### 5.3 向量化与入库

- 本地 embedding：`FastEmbedEmbeddings(model_name=BAAI/bge-small-zh-v1.5)`。
- FAISS 本地索引保存于 `data/vectorstore/`。
- `ingest_pdfs.py` 支持 `--rebuild` 重建；不指定时按文件名去重追加。
- **当前索引**：205 份文档、9807 个片段、含 `tier` 元数据与来源标签；2026-08-12 省级、园区、其他地区政策批量入库完成，根目录 PPTX 已入库（含 PNG/JPG 图片与 PPTX）；磁盘 215 个文件全部入库（10 个跨目录同名副本按 source 去重）；国家 457 页、省级 88 页、园区 38 页、其他地区约 16 页扫描件 OCR 缓存已生成。

### 5.4 检索（检索逻辑）

采用多层检索：

1. **混合检索**：BM25（jieba 中文分词）+ FAISS 向量相似度，用 `EnsembleRetriever` 合并。
2. **多问句扩展**：每次提问先让 DeepSeek 生成 3 个不同问法，与原问题一起检索，合并去重（`RETRIEVE_LIMIT=24` 上限）。
3. **章节结构扩展**：命中 `section_path` 时按“词越长越具体权重越高”打分排序，避免泛化词（如“数据”“企业”）把相关文档挤出结果。
4. **层级过滤**：`qa.detect_tier(question)` 识别问题中的层级词（“国家政策/国家级/全国/省级/全省/市级/全市/园区政策/其他地区”等）；指定层级时只在该层级文档中检索（层级内 BM25 + 全库向量排序后过滤到该层）；未指定时查全部政策。注意：裸“园区”不视为层级词，避免“园区数字孪生”被误判到空目录。**外省/外地兜底**：`REGION_KEYWORDS`（山东、济南、青岛、厦门、宁波、深圳、萧山、杭州、上海、北京、朝阳区、北京经济技术开发区、经开区）出现时，即使问题同时含“省级/市级”等层级词也跨层级检索，避免暂存园区目录的“语料券”资料包文件被过滤掉。
5. **指定文件检索**：`qa.detect_target_sources(question)` 识别问题中的书名号引用（如 `《大数据局反馈》`），匹配知识库文件名后只在这些文件中检索；没有答案时回委婉的未答说明。
6. **结果合并防淹没**：普通 BM25+向量命中优先，章节结构命中只用于补充，避免“数据/园区”等泛化词把真正命中的短文档挤出前 24；命中反馈类小文件（≤8 块）时整文件片段一起进入上下文，保证“修改建议一~四”等完整。
7. **总结/梳理类问题补全**：`_is_summary_question()` 识别“总结/梳理/汇总/概括/概述/归纳/说明/介绍/全部/完整/清单/一览/明细”等词；识别后把已命中来源的全部相关片段按来源补齐（小文件整文件、大文件按命中章节补全），上限 `SUMMARY_RETRIEVE_LIMIT`（默认 200）、`SUMMARY_FULL_SOURCE_MAX`（默认 120），并按来源/页码排序；多问句检索用 `SUMMARY_SEED_LIMIT`（默认 120）且按查询轮转合并，避免某个文件被其他文件挤掉。
8. **默认苏州/江苏语境过滤**：`_needs_other_region_docs(question)` 判断问题是否点名外地、问“其他地区/外地/不同地区”、问“语料券”或要求横向比较（对比/比较/不同/差异/区别/相比/横向/对照）；未触发时 `_local_source_names` 只允许国家/江苏/苏州/园区文档，以及“其他地区政策”目录中经“文件名外地标记 + 内容外地/本地标记”双重判断确认的江苏/苏州文档进入检索；触发时保持全库跨地区检索（`REGION_KEYWORDS` 兜底仍生效）。

### 5.5 回答（作答逻辑）

- 严格 grounding 提示词：只能使用“知识库内容”作答，禁止编造；提示词明确“同一文件可能被拆成多个片段，必须综合所有相关片段；未在知识库明确出现的奖项、数字、条款不得补充”。
- 总结/梳理/汇总/介绍类问题：先概括核心要点（通常 3~7 条），保留最重要的编号条目和关键数字；不要逐文件复制目标、任务和全部细项；用户明确要求“完整列出/全部条目”时才逐条列全。
- 列举类问题（“有哪些”“列举”）：把主要条目逐条列出，每条保持简短，不展开无关细节。
- 多文档总结/梳理类问题：每个要点后面标注（《文件名》）来源，方便溯源。
- 回答长度：先给核心结论/要点再按需补充，既不要冗长地逐文件铺开，也不要过于简洁；概括只能依据知识库内容，不得添加知识库之外的任何信息，不得臆测、扩写或补全。
- 多来源问题：先归纳共同的核心要点；确需区分文件时再按“《文件名》”分组，每个文件只保留关键要点；禁止把不同文件的条目混成一份清单；知识库不足时回委婉的未答说明。
- 判断类问题：先明确回答“是/不是”，再引用原文依据。
- 检索不到超过阈值的内容时，返回委婉的未答说明（“我还不懂这些，你可以换个问法再问一次。需要我帮你联网搜索相关的答案吗？”），不显示来源，也不要求用户上传或补充文档。
- 联网搜索整理回答：用户同意后，`answer_web_search` 先用上一个未答问题或当前问题联网检索，再让 DeepSeek 只依据搜索结果整理；答案开头固定追加 `> 以下内容来自联网搜索，并非官方文件内容，仅供参考，请谨慎辨别。`，`web=true`、sources 为空；搜索无结果/整理失败时返回“我尝试了联网搜索，但没有找到可靠的相关内容。你可以换个问法再问一次。”
- 回答附带来源：只列出命中的文档名，不显示页码。
- 结构化解读/报告：`_is_report_question()` 识别“解读/报告/汇报/提纲/白皮书/一页纸/主要内容/内容概要/要点/概况”；命中后改用 `REPORT_SYSTEM_PROMPT`，按“政策名称与基本信息、背景与总体目标、适用对象与适用范围、主要内容与重点任务、支持措施、申报要求与流程、实施期限与保障措施、依据文件与来源”组织，每个要点带（《文件名》）；没有知识库依据的小节必须省略，禁止编造，也不允许出现“知识库未提及/缺失”等评价知识库完整性的表述；整个报告无依据时只回委婉未答。

### 5.8 对话型问答（多轮承接）

- `answer_question(..., history=...)`：接受 `[{"role": "user"/"assistant", "content": "...", "sources": [...]}]`，最多保留 `MAX_HISTORY_TURNS=8` 轮（16 条消息）；`_normalize_history` 统一规范化 role/content/sources。
- `SYSTEM_PROMPT` 与 `REPORT_SYSTEM_PROMPT` 都加入“对话历史”区块：承接指代、自然对话语气、历史只用于理解指代不能作为新事实来源、历史回答均来自知识库可直接沿用、历史本身是委婉未答时仍回复委婉未答、严格不越库。
- 检索增强：`_conversation_queries` 先调用 `_resolve_referents` 做规则化指代替换。解析优先级：① 同一条消息内先按句切分（`_sentences`），取指代句之前最近的非指代句话题（`_extract_local_topic`），例如“数字孪生是什么？园区对它有什么期望吗？”直接解析为“园区对数字孪生有什么期望吗？”；② 历史中最近一轮用户问题本身含指代词时跳过该轮，继续向前找真正的话题（`_history_topic`）。`_extract_topic` 优先取书名号内容，多句时取第一句，再取去掉问句尾巴后的最长语义段。
- 再用 `REWRITE_PROMPT` 让模型改写为独立查询，改写失败则拼接上一轮用户问题与解析后的问题，随后照常做多问句扩展检索。
- `REWRITE_PROMPT` 明确要求“不得在改写结果中残留指代词”，`SYSTEM_PROMPT` 也加入了“先把指代词替换成历史中明确提到的具体对象”的示例。
- 回答措辞：`SYSTEM_PROMPT`/`REPORT_SYSTEM_PROMPT` 均禁止回答中出现“知识库/库内/知识库内容”等后台术语，要求用“根据我的理解”“从已有资料看”“据了解”等委婉表达；`_sanitize_answer` 对模型输出做最终清洗（先保护《书名号》内容，再替换残留“知识库”），`_answer_from_history` 与正常作答路径都会执行。
- 历史兜底：未命中新内容且有多轮历史时走 `_answer_from_history`，只依据历史对话中已有的回答承接，来源沿用历史回答的来源；报告模式不承接；模型返回委婉未答时来源清空。
- 联网搜索同意识别：`_should_web_search` 识别“可以/好的/同意/搜索/联网搜索/帮我搜/帮我查”等表达；仅回复“可以”等短同意时，`_web_search_query` 沿用上一个用户问题作为搜索词；用户直接说“帮我搜索一下XXX”也会触发联网搜索。
- `ask.py` 交互模式自动累积历史（保留最近 16 条消息）；命令行单问仍是无状态。
- 网页消息结构：`{role, content, sources, question, unknown, showDownload}`；欢迎语与首轮回答 `showDownload=false`，`unknown=true` 的消息也不渲染下载按钮。
- `AnswerResult` 新增 `unknown` 字段：委婉未答时置 `True`，`/ask` 响应同步返回，前端也按回答文案做兼容兜底。

### 5.10 Demo 版访问控制（2026-08-14 新增）

- 密码门开关：`config.demo_password()` 读取 `.env` 的 `DEMO_PASSWORD`；为空时鉴权完全关闭（本地开发不受影响），配置后网页和 API 都要求密码。
- 接口：`GET /auth/status` 返回 `{"enabled", "locked", "retry_after"}`；`POST /auth/check`（body `{"password": "..."}`）校验密码；`/ask`、`/export-pdf`、`/upload` 需带 `X-Demo-Password` 头，密码错误/缺失返回 401。
- 尝试限制与锁定：按 `X-Demo-Client-Id`（前端 localStorage 生成并持久化）记录失败次数；`MAX_DEMO_PASSWORD_ATTEMPTS=3`，第 3 次错误返回 429 并锁定 `DEMO_PASSWORD_LOCK_SECONDS=180`（3 分钟），锁定期间任何接口都返回 429，锁定结束后自动恢复并可重新尝试。
- 剩余机会提示：密码错误且未锁定时，401 `detail` 为“密码错误，还剩 N 次机会。”，前端直接展示后端文案。
- 前端登录浮层：页面加载时请求 `/auth/status`；密码启用则显示浮层，通过后把密码存入 `sessionStorage`（`policy-demo-auth-v1`）并在请求头带上；401/429 时清空并重新显示登录或锁定状态。
- 禁止粘贴：密码输入框监听 `paste`/`drop` 并 `preventDefault`，提示“密码不支持粘贴，请手动输入。”；`autocomplete="new-password"`。
- 本地状态键：`policy-demo-client-id`、`policy-demo-attempts`、`policy-demo-lock-until`（localStorage），`policy-demo-auth-v1`（sessionStorage）。

## 8. 踩过的坑 / 犯过的错误（重要）

1. **系统 Python 与虚拟环境混用**：直接 `python ingest_pdfs.py` 报 `No module named 'dotenv'`。解决：一律用 `.\.venv\Scripts\python.exe` 或 `run_*.bat`。
2. **API key 前缀**：最初给的是 `k-...`，DeepSeek 返回 401；更正为 `sk-...` 后可用。
3. **DeepSeek 无 embedding**：直接复用 OpenAIEmbeddings 会 404。解决：本地 `fastembed`。
4. **HuggingFace 无法直连**：官方域名超时；镜像能连但默认走 Xet 协议返回 401。解决：`HF_ENDPOINT=https://hf-mirror.com` + `HF_HUB_DISABLE_XET=1`。
5. **本地向量分数偏低**：BGE 分数 0.13~0.16，旧阈值 0.5 把所有相关内容过滤掉。解决：阈值降到 0.05，并改用混合检索。
6. **切块把标题挂在上一块尾部**：标题必须另起新块，并把标题和正文放同一片段，再维护 `section_path`。
7. **纯向量检索漏枚举章节**：“重点行动有哪些”必须把所有（四）~（十五）片段带进来。解决：BM25 + 章节结构扩展 + 多问句。
8. **模型列举不完整 / 不稳定**：提示词强制逐条列全、不得用“等”带过；章节结构片段优先进入上下文。
9. **端口 8000 冲突**：不要由 Codex 后台启动服务；由用户自己在 PyCharm 启动。
10. **沙箱后台服务调 DeepSeek 不可靠**：受限环境启动的服务，`/ask` 调 DeepSeek 曾报 `Connection error`。解决：服务由用户自己的终端/PyCharm 启动。
11. **Start-Process 在沙箱中报错**：PowerShell 同时存在 `Path` 和 `PATH`，`Start-Process` 报“字典中的关键字重复”。解决：用 `cmd /c start /b ...`（仅开发环境处理）。
12. **PowerShell 管道中文乱码**：通过 stdin heredoc 传入中文脚本会被转成 `?`。解决：把脚本写成 `.py` 文件用 UTF-8 保存，或把中文问题作为命令行参数传入。
13. **openpyxl 不支持 with 语法**：`with load_workbook(...) as wb` 报 `TypeError`。解决：手动 `wb.close()`（已用 try/finally 处理）。
14. **切块会把不同文件并进同一片段**：旧逻辑里相邻两个无章节文件可能合并成一个片段，来源标注也错。解决：`chunking.py` 在来源变化时强制断块。
15. **扫描 PDF 依赖 OCR 库**：`rapidocr-onnxruntime` 未安装时扫描页会跳过并打印提示；`pip install -r requirements.txt` 后即可自动识别。
16. **章节扩展被泛化词淹没**：加入多份文档后，“数据”“企业”等词会命中大量旧文档章节，新文档排不进前 24。解决：`qa.py` 按命中词长度加权打分。
17. **`.doc` 文件未支持**：用户放入市级政策的 6 份 `.doc` 目前会跳过（当前不支持该后缀），这是最近一次入库没有完成的原因之一。
18. **向量库未随目录分层重建**：目录分层和 `tier` 代码已就绪，但重建未执行，当前索引仍无层级信息；继续工作前必须先重建。
19. **用户反复强调不要提前结束对话（完成所有任务前不准停止！！！！！）**：中途停下等用户催促会造成很差体验，用户已多次批评“又停了”“要我说多少遍”；应一次把任务做完（含验证和文档更新）再结束，承诺“继续”就必须持续调用工具，不能停在文字上。
20. **Word COM 连续转换竞态**：`win32com.client.Dispatch` 可能绑定到未完全退出的旧 Word 实例，导致 `Visible` 设置失败；已改用 `DispatchEx`（每次新建独立实例）+ 失败重试 + 传入绝对路径。
21. **沙箱内无法启动 Office COM**：Codex 沙箱会话会报“指定的登录会话不存在”，此时会自动回退到内置 OLE 解析（同样能读出中文正文）；用户自己的终端/PyCharm 运行时会走 Word/WPS COM 精确转换。
22. **OLE `.doc` 不能只按 `fcMin/lcbMin` 读正文**：Word/WPS 文件常含 CLX 段表，需解析 CP/Pcd 段才能完整取回正文；已用 `olefile` 实现该兜底。
23. **空层级检索崩溃**：问“园区政策有什么”这类带层级词、但该层级目录为空的问题时，`BM25Retriever.from_documents([])` 内部 `texts, metadatas, ids = zip(*generator)` 会报 `not enough values to unpack (expected 3, got 0)`。解决：`qa.py` 在 `tier_documents`/`pool` 为空时不创建 BM25Retriever，直接返回空结果并回“我不知道”。
24. **短文档被泛化章节挤掉**：`大数据局反馈` 这类无标题短文档的片段带 `section_path` 空值，问题里的“数据”等词会命中大量行动计划章节，结构命中优先合并把真正命中的文档挤出前 24。解决：正文/片段注入来源标签；合并时普通命中优先占一半，结构命中只补漏；书名号点名文件时限定该文件检索。
25. **“园区”被误判为政策层级**：`detect_tier` 曾把“园区数字孪生相关成果获得了什么奖项”里的“园区”识别为“园区政策”，而 `04园区政策` 为空目录，直接返回“我不知道”。解决：去掉裸“园区”别名，只保留“园区政策”等明确表达。
26. **同文件上下文不全导致回答不全/幻觉**：反馈类文档被切成多块，只命中 1 块时模型看不到“修改建议二~四”等其余内容。解决：`_merge_results` 对命中的小文件（≤8 块）整文件带入上下文；prompt 增加“综合同一文件所有片段、未在知识库出现的奖项/数字/条款不得补充推测”。
27. **超长扫描 PDF 一次跑不完**：457 页扫描件单页 RapidOCR 约 10 秒，串行需约 80 分钟，30 分钟工具超时会中断。解决：新增页面级 OCR 缓存（`data/ocr_cache/`）+ 多进程并行预识别；中断后重跑会跳过已识别页。
28. **多进程 OCR 加速有限**：RapidOCR 单页已占用多核，4 进程并行约 1.3 倍加速；真正解决超长文档的是页面缓存续跑，而不是盲目加大进程数。
29. **OCR 缓存按 DPI 隔离**：缓存 key 包含 `PDF_OCR_DPI`；同一文件用不同 DPI 会分别缓存，重建时保持相同 DPI 才能复用。
30. **总结问题跨文件混答/条目不全**：旧逻辑只对“有哪些/列举”加大检索，总结/梳理类问题未识别；大文件只带回命中片段导致中间条目缺失，多份文件的小点混在一起。解决：`_is_summary_question` 识别总结/梳理/汇总等词；`_complete_source_context` 按来源补齐片段并按来源/页码排序；提示词强制按文件分开作答。
31. **多问句种子检索挤占**：多个检索问法先合并再去重时，第一个问法的 120 条结果会占满种子上限，后面问法命中的文件进不了上下文。解决：`invoke_multi` 改为按查询轮转合并，每个问法轮流贡献结果。
32. **种子上限与上下文上限相同导致无扩容空间**：`SUMMARY_SEED_LIMIT=200` 时种子已填满 200 条，`_complete_source_context` 无法再补齐；解决：种子 120、上下文 200，并按来源优先补全。
33. **严格阈值被宽松模式破坏**：`relax_threshold` 若对所有列举/多少类问题生效，会绕过 `SCORE_THRESHOLD`；解决：只对明确“总结/梳理/汇总”类问题放宽。
34. **测试硬编码文件名、扩展名清单重复维护**：旧 `tests/test_pipeline.py` 散落 `"规则.txt"`、`"大数据局反馈.doc"` 等字面量，`self_check_learning.py` 又复制一份 `SUPPORTED_SUFFIXES`；解决：测试文件名集中为顶部常量，自检工具直接引用 `loaders.SUPPORTED_SUFFIXES`。
35. **入库未设 `PDF_OCR_DPI` 导致 457 页重新 OCR 超时**：旧 OCR 缓存按 dpi=100 保存，直接跑 `ingest_pdfs.py` 默认 dpi=200，缓存全部不命中，457 页重新 OCR 30 分钟超时。解决：入库/重建前统一 `$env:PDF_OCR_DPI='100'`（或用与缓存相同的 DPI）。
36. **WPS 生成 docx 带 `Target="NULL"` 伪关系**：文件是合法 zip 且含 `word/document.xml`，但 python-docx 按关系遍历 part 时读 `NULL` 条目抛 `KeyError`。解决：`_load_docx` 捕获 `KeyError` 后走 `_load_docx_xml()` 直接从 `word/document.xml` 提取正文+表格。
37. **自检整行匹配对跨块表格行误报**：`self_check_learning.py` 曾要求每个原始行整行出现在向量库拼接文本中；超长表格行被 chunk 边界从中间切开后整行无法匹配，误报“missing raw lines”（实际内容完整）。解决：整行匹配失败时按 `|`/标点/空白拆成片段逐段确认，全部在库则通过。
38. **跨目录同名扫描件 OCR 噪声导致自检误报**：同一份扫描 PDF 同时放在 `04园区政策/` 和 `05其他地区政策/` 时，两个路径分别 OCR（缓存 key 按路径隔离），识别文本有少量噪声差异，自检对两个路径都做整行比对会误报。解决：`self_check_learning.py` 按 source 去重（同名文件只检查一次），并输出 `duplicate_sources` 计数。
39. **根目录文件被误标层级**：`_tier_from_path` 直接取父目录名，`data/pdfs/` 根目录的父目录名是 `pdfs`，导致根目录文件被错误标成 `tier="pdfs"`。解决：层级识别显式排除知识库根目录（`path.parent.resolve() == pdf_dir().resolve()` 时返回空 tier）。
40. **PowerShell 里 curl 传 JSON 花括号被破坏**：`curl -d "{\"question\":...}"` 花括号/引号被 PowerShell 解析坏，报 `unmatched close brace`。解决：先用 `Set-Content` 写临时 JSON 文件，再 `curl --data "@file"`。
41. **Python 控制台打印中文/符号在 GBK 下崩溃**：PowerShell 默认 GBK，打印中文或 `•` 报 `UnicodeEncodeError`。解决：设 `$env:PYTHONIOENCODING='utf-8'`，或脚本只打印 ASCII 摘要。
42. **`view_image` 在本环境返回 Unsupported Image**：无法用图片预览确认 PDF 排版。解决：用 PIL/numpy 统计非白像素比例验证非空白，用 pymupdf `page.get_text()` 验证中文正文存在。
43. **工作目录不是 git 仓库**：`git diff` 报 `Not a git repository`。解决：直接读文件/用 `Select-String` 核对改动，不依赖 git。
44. **8000 端口被非 `.venv` 的 Python 占用**：本环境出现过 `C:\Users\29526\.cache\codex-runtimes\...\python.exe` 监听 8000，容易误判“新代码没生效”。解决：`netstat -ano | findstr :8000` 拿 PID，再 `Get-Process -Id` 看启动时间与路径；`index.html` 改后浏览器强刷即可，`server.py`/`qa.py` 改后必须重启进程。
45. **对话轮次没收尾被用户追问“你怎么了”**：一次对话窗里执行完工具后必须给出最终回复；用户连续催促“不要停”时，同一轮内把所有实现、测试、验证、文档更新做完再结束。

61. **`str.strip("...\s")` 里 `\s` 不是字符类**：会产生 `SyntaxWarning: invalid escape sequence '\s'`，且不会按空白字符去除；解决：显式写 `" \t\r\n"`。

## 9. 用户当前状态与使用流程

1. 用户在 PyCharm 打开项目，解释器选 `.venv`。
2. 用户自己运行 `run_server.py` 或 `.\run_server.bat`，然后浏览器打开 `http://127.0.0.1:8000`。
3. 用户本地把新文档放入 `data/pdfs/` 对应层级目录（01国家政策 / 02省级政策 / 03市级政策 / 04园区政策 / 05其他地区政策），再运行 `.\run_ingest.bat` 入库。
4. 网页用于多轮问答，聊天型界面：用户气泡在右、助手气泡在左；左侧边栏保存/切换/删除对话；第一轮与未知回答不显示下载按钮，后续正常回答右下角小图标可导出整段对话 PDF；来源默认收起，点“来源 (N)”下拉展开。
5. 未答时网页会显示“需要我帮你联网搜索相关的答案吗？”和“联网搜索”按钮；回复“可以”或点按钮即可联网搜索，联网回答带“联网搜索”徽标和“请谨慎辨别”声明。
6. 默认问题只围绕苏州/江苏/园区作答；需要横向比较或点名外地时（如“苏州和上海有什么区别”“上海市数据条例有哪些规定”），再引入外地政策。
7. demo 多人试用：打开公网链接（见第 12 节）→ 手打输入密码（不能粘贴）→ 密码错误会提示“还剩 N 次机会” → 同一浏览器最多 3 次，第 3 次后锁定 3 分钟 → 通过后正常多轮问答。
8. demo 结束：关闭 cloudflared 隧道（`Stop-Process -Name cloudflared`）和 8000 服务；trycloudflare 链接是随机临时的，重启后需重新生成。
